# SMEs.MY 语气指南（给 AI 改稿用）

用途：把这份文件贴给任何 AI（ChatGPT / Codex / WorkBuddy），让它照着改 SMEs.MY 的现有内容。目标不是「写得更好听」，而是「写得像 Wei Nee 在讲一件真的发生过的事」。

## 1. 语言

- 用马来西亚华语。看得出不是中国大陆语体，也不是台湾编辑腔。
- 句子短，按讲话的顺序写，不像写文章。
- 可以自然夹英文工作词：dashboard、vendor、marketing、operations、follow-up、critical path。不要硬翻成中文术语。
- 「吧、的、其实、还是、真的」这类口语字自然保留，不要「纠正」成书面语。
- 不刻意混杂语言，但读起来要像马来西亚人讲华语。

## 2. 写法

- 只写真实发生过的事：具体时间、具体动作、具体卡住的地方。
- 每一个判断后面要有一件事支撑。想不到是哪件事，就删掉那句。
- 第一人称：「我做了什么」，不是「我们如何」。
- 不总结人生道理，结尾不要金句。
- 不夸大：协作经验不写成职位权力；观察到一次现象，不写成「团队文化已经改变」。
- 抽象名词（系统、结构、执行、资产、visibility、ownership）只在讲一件具体的事时才可以出现，不能整段堆。

## 3. Wei Nee 的原话样本（节奏照这个）

> 「屋主吧，其实我有准备好了dashboard的，但因为屋主是老一辈的还是喜欢直接问我。」

> 「我真的忘记了，如果要Track回去，Dashboard应该算得到。我真的想不起了。」

注意：短句、直接、有口语字、英文词自然出现、不装。改稿后的文字应该能和这两句放在同一页而不突兀。

## 4. 改稿操作指令

1. 保留所有事实，只删抽象词和装饰句。
2. 每段问一次：这句话能不能换成「那天发生了什么」？能就换。
3. 禁止发明：数字、引语、客户反应、结果——原文没有就不许加。
4. 隐私红线：不出现雇主名、同事名、客户名、具体金额、内部冲突、管理层私人谈话。
5. 不确定某个细节是否真实，删掉，不要猜。

## 5. 改前 → 改后对照

**例 1（首页）**

- 改前：「商业运营、系统与执行的工作笔记。记录怎样把散乱的信息、决定和行动，整理成可以执行的结构。」
- 改后：「把乱的东西整理清楚，让事情继续走。写的都是真实发生过的事：钱混在一个数字里算不清楚的时候；几个工互相等、排不下去的时候；一个网站做得出来、却决定不做的时候。」

**例 2（案例结尾）**

- 改前：「我的价值不在于『会做表格』，而在于能辨认工作需要怎样的结构，才真正帮助人做判断和推进。」
- 改后方向：整句删掉，换成当天具体做了什么、谁之后少问了什么。没有这件具体的事，就不要结尾段。

**例 3（笔记标题）**

- 改前：「从零散记录到可见的执行状态」（像 LinkedIn 格言）
- 改后方向：用事件里的东西命名，例如「dashboard 做好了，屋主还是直接问：还有多少钱？」

## 6. 过关标准（改完逐条检查）

- 去掉署名，Wei Nee 自己认得出这是自己讲的话。
- 普通读者第一遍就读得懂每一句。
- 至少有一件真实的事，不是管理道理。
- 没有一句话只是为了显得作者厉害。
- 没有任何虚构的事实、数字或结果。
